#### Timer lifecycle (derived, no parallel persisted state machine)

IDLE: no current timer/ready event. RUNNING: existing timer phase.running with endDate. PAUSED: same timer phase.paused with frozen remaining seconds. FINISHED: existing engine clears timer and publishes restReadyExerciseID, existing haptic once, short ready popup. DISMISSED: skip or ready-popup dismissal clears presentation/event and returns to IDLE. DISMISSED is a transition, not a second stored timer phase. Navigation changes the presentation host only, never copies timer data.

Local sound/notification is scheduled only if permission was previously granted/provisional, and only enables sound when system settings permit it. No permission request added. One identifier replaces/cancels prior pending notifications. Cannot guarantee automatic Activity ending or app haptic delivery while the app is killed; staleDate/date text and foreground reconciliation are not claims of continuous execution.
